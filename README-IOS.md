## 1. Architecture Overview

```
┌──────────────────────────────────────────────────────────┐
│                     iOS Native App                        │
│  ┌────────────────────────────────────────────────────┐  │
│  │           Capacitor Native Bridge                  │  │
│  │  @capacitor/haptics  @capacitor/push-notifications │  │
│  │  @capacitor/network  @capacitor/app                │  │
│  └─────────────────────────┬──────────────────────────┘  │
│                             │ WKWebView                   │
│  ┌──────────────────────────▼──────────────────────────┐ │
│  │         https://wellness-and-sea.vercel.app          │ │
│  │         (Next.js SSR — loads live from Vercel)       │ │
│  └─────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

**Key decisions:**

| Decision | Reason |
|---|---|
| Live URL mode (not static export) | Next.js uses Server Actions & API routes — can't be statically exported |
| `capacitor://wellness-and-sea` custom scheme | For push notification deep links only |
| Email/Password auth on iOS (no Google) | Apple Guideline 4.8 compliance — no "Sign in with Apple" required |
| NativeProvider in RootLayout | Single initialisation point; no-op on web |

## 2. Repository Structure

```
wellness-and-sea/
│
├── capacitor.config.ts          ← Capacitor configuration (appId, server.url, plugins)
├── ios/                         ← Generated by `npx cap add ios` — Xcode project lives here
│
├── src/
│   ├── lib/
│   │   ├── platform.ts          ← SSR-safe isNativePlatform(), isIOS(), getPlatform()
│   │   ├── actions/
│   │   │   └── auth.ts          ← signIn, signUp, signInWithGoogle, sendOtp, verifyOtp
│   │   └── native/
│   │       └── push-notifications.ts  ← initPushNotifications(), saveDeviceToken()
│   │
│   ├── hooks/
│   │   ├── usePlatform.ts       ← React hook: { isNative, isIOS, platform, isReady }
│   │   ├── useHaptics.ts        ← React hook: { impact, notification, selection }
│   │   └── useNetwork.ts        ← React hook: { isOnline, connectionType }
│   │
│   └── components/
│       └── native/
│           ├── NativeProvider.tsx    ← Mounted in RootLayout; inits all native features
│           └── (add future native components here)
│
└── README-IOS.md                ← This file
```

**Rules for adding native code:**
- All Capacitor plugin imports must be inside `if (isNativePlatform())` guards  
- Dynamic `import()` inside the guard is preferred to avoid SSR loading the plugin code  
- Never import Capacitor plugins at the top of a file without a platform check  
- All native-only components go in `src/components/native/`  
- All native-only utilities go in `src/lib/native/`

## 3. One-Time Local Setup

```bash
# 1. Clone the repository
git clone https://github.com/oriyaish2000-OriY/wellness-and-sea.git
cd wellness-and-sea

# 2. Checkout the iOS branch
git checkout feature/ios-capacitor-prep

# 3. Install dependencies (includes @capacitor/* packages)
npm install

# 4. Build the Next.js app for Capacitor
#    (Not required in server.url mode, but needed for `npx cap sync`)
npm run build

# 5. Add the iOS platform (FIRST TIME ONLY — generates ios/ folder)
npx cap add ios

# 6. Sync web assets and plugin configs into Xcode project
npx cap sync ios

# 7. Open Xcode
npx cap open ios
```

> **Re-sync after web changes:** Any time you change `capacitor.config.ts` or add/remove plugins, run `npx cap sync ios` before building in Xcode.

## 4. Domain & Deep Link Configuration

### 4a. Custom URL Scheme (for push notification deep links)

In Xcode, the custom scheme `wellness-and-sea://` is registered automatically by Capacitor when you run `npx cap sync`. Verify:

1. Open Xcode → select the `App` target → `Info` tab  
2. Scroll to **URL Types** → should see:
   - **Identifier:** `com.wellnessandsea.app`
   - **URL Schemes:** `wellness-and-sea`

If missing, add it manually with the values above.

### 4b. Associated Domains (for Universal Links — optional, future)

Universal Links allow tapping `https://wellness-and-sea.vercel.app/booking/xxx` to open the app directly. This requires:

1. A valid SSL certificate on the domain (Vercel provides this automatically)
2. An `apple-app-site-association` file at `https://wellness-and-sea.vercel.app/.well-known/apple-app-site-association`
3. In Xcode: `Signing & Capabilities` → `+ Capability` → `Associated Domains` → add `applinks:wellness-and-sea.vercel.app`

**Skip for first release.** Universal Links are a polish feature; the custom scheme is sufficient.

## 5. Supabase Auth Configuration

Log in to the Supabase Dashboard: https://supabase.com/dashboard/project/qfrjvkfrzdsrfxjmxxop

### 5a. Allowed Redirect URLs

Go to **Authentication → URL Configuration** and ensure ALL of these are listed:

| URL | Used For |
|---|---|
| `https://wellness-and-sea.vercel.app/auth/callback` | Web login (Google OAuth, email links) |
| `http://localhost:3000/auth/callback` | Local development |
| `wellness-and-sea://auth/callback` | Future: custom scheme deep links |

Click **Save** after adding.

### 5b. Email OTP

Email OTP is enabled by default in Supabase. Verify:

1. **Authentication → Providers → Email** — ensure **Enable Email Provider** is ON
2. **Confirm email** can be OFF for faster onboarding, or ON for security
3. **OTP Expiry:** Default 3600 seconds (1 hour) — acceptable

### 5c. Google OAuth (web only — NOT used on iOS)

If not already configured:

1. **Authentication → Providers → Google** → Enable
2. Paste your Google Cloud **Client ID** and **Client Secret**
3. Copy the **Callback URL** from Supabase and paste it into Google Cloud Console → OAuth Credentials → Authorized Redirect URIs

## 6. Xcode Setup

After running `npx cap open ios`, complete these steps in Xcode:

### 6a. Bundle Identifier

1. Select the **App** target → **General** tab
2. Set **Bundle Identifier:** `com.wellnessandsea.app`  
   *(Must match `appId` in `capacitor.config.ts`)*

### 6b. Display Name

- **Display Name:** `Wellness & Sea`

### 6c. Deployment Target

- **Minimum Deployments:** iOS 16.0 (covers ~98% of active devices as of 2026)

### 6d. Signing

1. **Signing & Capabilities** tab
2. Check **Automatically manage signing**
3. **Team:** Select your Apple Developer account team
4. Xcode will auto-create the provisioning profile

### 6e. Capabilities

Add these capabilities (click `+ Capability`):

| Capability | Why |
|---|---|
| **Push Notifications** | Required for `@capacitor/push-notifications` |
| **Background Modes** → Remote notifications | Allows silent push to refresh content |

### 6f. App Icon

1. In Xcode, open `App/App/Assets.xcassets/AppIcon.appiconset`
2. Drag in your icon files at these sizes:
   - 1024×1024 (App Store)
   - 180×180 (iPhone 3x)
   - 120×120 (iPhone 2x)
   - 87×87, 80×80, 60×60, 58×58, 40×40, 29×29, 20×20

> Use https://www.appicon.co to generate all sizes from a single 1024×1024 PNG.

### 6g. Launch Screen

Edit `App/App/Base.lproj/LaunchScreen.storyboard` or use `App/App/Assets.xcassets/Splash.imageset`.  
Capacitor generates a default; replace with the brand's sand (#faf5ee) background + logo.

## 7. Native Plugin Reference

| Plugin | Package | What it does | Fallback on web |
|---|---|---|---|
| Core | `@capacitor/core` | Platform detection, plugin bridge | Returns `false` / stubs |
| App | `@capacitor/app` | App lifecycle, deep links | No-op |
| Haptics | `@capacitor/haptics` | Taptic Engine feedback | Silent no-op |
| Push Notifications | `@capacitor/push-notifications` | APNs registration & delivery | No-op |
| Network | `@capacitor/network` | Real connectivity status | `navigator.onLine` |

### Using a plugin (correct pattern)

```typescript
// ✅ CORRECT — guarded, dynamic import
import { isNativePlatform } from '@/lib/platform'

async function doNativeThing() {
  if (!isNativePlatform()) return          // web guard
  const { Haptics, ImpactStyle } = await import('@capacitor/haptics')
  await Haptics.impact({ style: ImpactStyle.Light })
}

// ❌ WRONG — unguarded top-level import can cause SSR errors
import { Haptics } from '@capacitor/haptics'
Haptics.impact(...)
```

### Adding a new plugin

```bash
npm install @capacitor/PLUGIN-NAME
npx cap sync ios   # syncs the Swift/ObjC bridge into Xcode
```

Then add calls following the pattern above.

## 8. Authentication on iOS

### Why not Google Sign-In?

Apple Guideline 4.8 states:  
> *"Apps that use a third-party or social login service to set up or authenticate the user's primary account with the app must also offer Sign in with Apple."*

To avoid implementing "Sign in with Apple" (complex, more infrastructure):  
→ The Google Sign-In button is **hidden on iOS** (`!isNative` conditional in `login/page.tsx` and `signup/page.tsx`).  
→ iOS users authenticate with **Email + Password only**.

### Auth flow on iOS

```
User opens app
      │
      ▼
/auth/login  ─── Email field ──► signIn() Server Action
             ─── Password field ─► (password auth via Supabase)
                                    │
                                    ▼
                              Session cookie set in WebView
                                    │
                                    ▼
                              Redirect to dashboard
```

### OTP Flow (alternative, already implemented)

`sendOtp()` and `verifyOtp()` server actions are ready in `src/lib/actions/auth.ts`.  
To use OTP instead of password on iOS, create a new route `/auth/otp` using these actions.

## 9. Build, Archive & Upload

### Development build (simulator)

```bash
npm run build         # build Next.js (updates out/ for cap sync)
npx cap sync ios      # sync into Xcode project
npx cap open ios      # open Xcode
# In Xcode: select simulator → ▶ Run
```

### TestFlight build

1. In Xcode: `Product → Scheme → Edit Scheme` → set to **Release**
2. Select **Any iOS Device (arm64)** as the target (not a simulator)
3. `Product → Archive`
4. Xcode Organizer opens → click **Distribute App**
5. Choose **App Store Connect** → **Upload**
6. Accept all defaults → click **Upload**
7. In App Store Connect: **TestFlight → Builds** → wait for processing (~15 min)
8. Add internal testers → send invitation

### Production submission

Same as TestFlight but in App Store Connect:
1. Go to your app → **+ Version**
2. Select the build that passed TestFlight
3. Fill in release notes (Hebrew + English)
4. Submit for Apple Review (~24–48 hours)

## 10. TestFlight QA Checklist

Execute on a **physical iPhone** (not simulator) with iOS 16+.

### Authentication
- [ ] App launches without crash
- [ ] Login page shows: Email field, Password field, Login button
- [ ] **Google button is NOT visible** (critical — Apple review will reject if present)
- [ ] Login with valid email/password → redirects to correct dashboard

## 11. Environment Variables & Secrets

The iOS app loads the live Vercel deployment — it has **no local environment variables**.  
All secrets are stored in Vercel's Environment Variables (already configured):

| Variable | Location |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Vercel Dashboard → Environment Variables |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Vercel Dashboard → Environment Variables |
| `SUPABASE_SERVICE_ROLE_KEY` | Vercel Dashboard → Environment Variables (server-only) |
| `ANTHROPIC_API_KEY` | Vercel Dashboard → Environment Variables |

**APNs credentials** (needed when implementing server-side push sending):
| Item | Where to get it |
|---|---|
| APNs Auth Key (.p8 file) | Apple Developer → Certificates, IDs & Profiles → Keys |
| Key ID | Same page |
| Team ID | Apple Developer → Membership |

Store these in Supabase Edge Function secrets or Vercel Environment Variables.

## 12. Troubleshooting

### `npx cap add ios` fails
- Ensure Xcode is installed and `xcode-select --print-path` returns a valid path
- Run `sudo xcode-select --switch /Applications/Xcode.app`
- Accept Xcode license: `sudo xcodebuild -license accept`

### WebView shows "Failed to load" 
- Check that `capacitor.config.ts` `server.url` is correct
- Verify the Vercel deployment is running: `curl -I https://wellness-and-sea.vercel.app`
- In Xcode, check the device console (Window → Devices and Simulators → Console)

### Push notifications not working
- Simulator does NOT support push notifications — test on a real device
- Ensure `Push Notifications` capability is added in Xcode
- Check APNs certificate/key hasn't expired in Apple Developer portal

### Google button visible on iOS
- Symptom: Apple guideline 4.8 violation risk
- Cause: `usePlatform()` returning `isNative: false`
- Check: `window.Capacitor` exists and `isNativePlatform()` returns `true` in the WebView console
- Fix: Add `console.log(window.Capacitor)` in `NativeProvider.tsx` useEffect to debug

### Session lost on app reopen
- Supabase auth session is stored in a cookie in the WKWebView
- WKWebView cookies persist across app restarts by default
- If session is lost: check Supabase `Auth → Settings → JWT Expiry` — default 3600s may be too short; increase to 604800 (1 week)

### Hebrew text not RTL in WebView
- The `<html dir="rtl">` is set in `src/app/layout.tsx` — this flows into the WebView
- If a specific component looks LTR, check for missing `dir="rtl"` or `text-right` classes
